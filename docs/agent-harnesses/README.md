# Agent environments: evidence and case studies

These research notes record outcomes before promoting a workflow into a reusable
skill. They are preliminary observations, not rankings of agent products.

Keep three things separate:

- **Environment or harness:** the app supplying tools, context, permissions,
  continuation and user interaction.
- **Model:** the model generating the responses. A displayed name is not proof
  of the actual served model, reasoning configuration or billed rate.
- **Execution strategy:** scope, context reads, verification selection,
  checkpoints and stopping behavior.

## Cases

- [Copilot research-app build, November 2026](copilot-research-app-case-2026-11.md): useful implementation, incomplete product and insufficient spend visibility. Public summary; underlying project/account records remain private.

For future cases record the starting scope, client/model identity and confidence,
instructions actually loaded, implementation outcomes, independent acceptance,
repairs, usage evidence and missing facts. Separate model-quality acceptance from
deterministic fixtures and regression checks. Do not infer a product completion
percentage from passing-test counts.

Project-specific raw evidence belongs in its authorized private store. Put the
cross-project analysis here; put a tested executable workflow in Galing Skills
when there is enough evidence to justify it. Do not duplicate a private case or
publish account screenshots to make the public summary look more complete.
